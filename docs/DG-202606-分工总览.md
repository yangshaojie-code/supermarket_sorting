## 两人怎么拆

短期一人一块，**训练出第一版 9 类 YOLO 之前不要在检测头上互相改同一文件**。算法线用官方 `kele.pt` 继续做运动；数据线圈定采集脚本、数据集和训练配置。

```text
A  仿真采图 → 自动/半自动标注 → 微调 YOLOv8 → 交出 supermarket9.pt
B  平台已迁部分之上：对着货架、雷达走、抓放、把编排接到真动作
        │
        ▼  第一版 9 类权重进 weights/ 之后
A+B  一起：漏检难例、GS=0/1 外观差、抓空/错类、绕障超时
```

| | A 数据采集与 YOLO | B 迁移与算法 |
| --- | --- | --- |
| 目标 | 官方仿真外观下能分清 9 个 `kind` 的 `.pt` | Client 能按任务 JSON 完成尽可能多的取送循环 |

## 必须对齐的接口（两人公约）

任务 JSON 的 `kind` 只能是下面 9 个字符串，顺序建议作为 YOLO 类别 id 0–8（与 `runtime/task_protocol.py` 中 `KNOWN_KINDS` 一致）：

1. `sanmingzhi` 三明治  
2. `heweidao` 核味道  
3. `shupian` 薯片  
4. `zhijin` 纸巾  
5. `maidong` 脉动  
6. `kouxiangtang` 口香糖  
7. `pingguo` 苹果  
8. `chengzi` 橙子  
9. `kele` 可乐  

A 交出的 `data.yaml` / 权重类别名必须与上表**逐字相同**。B 把 `perception/yolo_backend.py` 里现在的 `CLASS_NAMES = ["kele"]` 换成这 9 项，并用 A 的 `.pt` 替换默认 `weights/kele.pt` 路径。

其它硬约束：

- 评测 **无网**。权重放进 `supermarket_sorting_baseline/weights/`，随 Client 挂载。
- Client 镜像：Ubuntu 22.04、PyTorch 2.7.1+cu128、**ultralytics 8.0.196**。不要升级 ultralytics 去跑 YOLO-World，除非把兼容 wheel **整包**打进仓库。
- 推理不得把 Server 未下发的坐标当真相；**训练时**用仿真真值投影打框是允许的，且应写在训练脚本里，不要写进评分 Client。
- `ROS_DOMAIN_ID=99`。文旅和零售镜像不要同时开。
- Shell 脚本保持 **LF**。不要在 `source /opt/ros/humble/setup.bash` 之前 `set -u`。
