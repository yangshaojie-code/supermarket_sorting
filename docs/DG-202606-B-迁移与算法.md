#### 依赖：评测镜像里没有 Nav2

零售官方 README / 赛题目录 **没有写死**「Client 评测断网」。我们文档里曾经写的「评测无网」是推断（文旅镜像叫 `offline-client`、权重须随仓库提交），**不能当成赛题原文**。

能确定的是官方 Client 镜像（`docker/client/Dockerfile`）只装了 `ros-humble-ros-base`、tf2、cv-bridge 和消息包，**没有** `ros-humble-navigation2`。评测挂的是这张离线 tar，不是现场再 `apt install`。

因此：

- **评分默认路径**就是现有自研：`scan` + `odom` + TF + `RosRobotController`（见下）。
- **不要**用 `ping` / `curl` 判断「有网就启用 Nav2、没网就用自己的」。有网 ≠ 镜像里有 Nav2，也 ≠ 评测允许 `apt`/`pip`；本机 host 网络能上网、现场装不上，两套行为对不齐。
- 若本机额外装了 Nav2、只想做对照实验：检查 **包在不在**（`ros2 pkg prefix nav2_bringup`），没有就走自研。对照代码不要进评分入口。
- GitHub 上的 Nav2 / 独立 DWA 仓库（如 [navigation2](https://github.com/ros-navigation/navigation2) `humble`、[custom_dwa_planner](https://github.com/koyaneni-yaswanth/custom_dwa_planner)）只作算法参考。可把 Python DWA 核心 **拷进** `runtime/`；不要把 Nav2 当评测依赖。

输入话题（`runtime/ros_contract.py`）：

- `/slamware_ros_sdk_server_node/scan`（360 点，`laser`）
- `/slamware_ros_sdk_server_node/odom`
- `/tf`、`/tf_static`

速度必须走 `RosRobotController`（clip ±0.35 / ±0.65），不要绕开限幅直接发 `cmd_vel`。不需要 SLAM：场景固定、官方保证货架入口到配送台有通路。
